# Known limitations

HAOS is development, not an accepted production distribution. The master prompt remains the complete target.

- The bounded installed foundation gate passed at `2cebd11`: exact ISO bytes verified, actual UEFI/TCG installation and both guest receipts completed, covering Hermes health, fixture volume boundaries, observer/local-network denial, staged local recovery, UI/backend restart separation and offline queue persistence. The earlier policy-umask, DNS and systemd/procfs startup failures are corrected and evidenced. This does not accept the complete production distribution, graphical owner onboarding or physical hardware. Historical billing failures are distinct from current public-repository runs. Builds remain unsigned. Full SBOM/provenance, reproducible pins, Secure Boot/private updates unfinished.
- Writable binds now receive root-broker named-agent ACLs on ext4/XFS/Btrfs with generation-aware original-permission recovery, and FAT/NTFS3 use verified agent masks. New real multi-filesystem and installed foreign-owner acceptance remain pending; scratch filesystem probes failed with EOPNOTSUPP, not success. External chmod/permission changes require stopped-runtime refresh; no continuous rights override exists. Same-system-disk data is conservatively denied. LUKS unlocking is owner work; hotplug/remote filesystems unsupported. See [volume access](VOLUME-ACCESS.md).
- Shared host networking now has a required socket-UID nftables guard for local/private destinations with narrow backend/DNS/reply exceptions. At `2cebd11`, the real runner kernel probe passed IPv4/IPv6/mapped-address denial, existing-connection revocation, backend self/reply exceptions, denied firewall mutation and preserved other-UID traffic. Both installed boots separately proved service-UID denial of a privileged localhost listener. AF_UNIX abstract sockets, resolver-change brokerage and complete egress/exfiltration policy remain incomplete. Inherited SELinux permissive configuration has no enforcing proof.
- Durable native missions now have a separate authenticated Telegram/Discord ingress, root-only pairing/credential CLI and durable transport inbox/outbox. Managed local chat and existing voice-transcript callers use the same persistent controller; opaque admission receipts survive UI reload without resending. Local ordinary, actual Unix-peer and root-private-file probes passed; bundled adapter constructors/contracts were verified without connecting. Real provider/gateway round trip and new installed-service acceptance remain unverified. Attachments, complete voice-response playback, pause/resume and WhatsApp/other adapters remain incomplete; see [gateway integration](GATEWAY-MISSIONS.md) and [native conversation](NATIVE-MISSIONS.md).
- Complete upstream turn is not independent goal proof. Ambiguity blocks intentionally. Background cleanup, resumable downloads and parallel worktrees need further work.
- Native host GUI bridge access is withheld; safe broker, genuine capture and authenticated remote stream missing.
- Autonomous themes/skills lack accepted capability manifests, isolated generation/test, whole-theme atomic swap/watchdog/revocation.
- Credential-isolated provider routing now has an owner CLI for actual pinned Codex OAuth, OpenAI/OpenRouter API keys and explicit compatible loopback models. Local HTTP, private-file/UID, interrupted-switch and pinned native resolver/Responses contracts passed; new kernel/socket/ISO acceptance remains pending. Real Codex/Telegram credentials were not supplied, so external model/tool/gateway turns are blocked, not claimed successful. General vault/log encryption, monetary/per-mission budgets, additional providers and graphical provisioning remain open. See [provider setup](PROVIDER-SETUP.md). No provider-less probe proves a real model/Git mission.
- New task/event/error/result text is redacted before persistence, including known backend credentials and recognizable credential formats. Unknown secrets, historical rows, upstream logs, screenshots, complete encryption and retention remain incomplete; see [mission privacy](MISSION-PRIVACY.md).
- Observer accounts reject inherited administrator groups, empty passwords and sudo authority before session start. Actual runner account/NOPASSWD/sudoedit probes and both installed guest observer checks passed at `2cebd11`. Separate password-authenticated fixed owner CLI remains. A new independent tty2 console supplies initial owner onboarding, single-use recovery codes/password reset and a required owner-readiness gate before autonomous execution. Root hash/replay/rotation/backoff/corruption probes passed locally; matching installed enrollment/reboot/recovery receipts are still required. Graphical wizard/locking, recovery media, automatic observer display behavior and all polkit/SELinux/custom identity reviews remain open; see [owner recovery](OWNER-RECOVERY.md).
- Owner-only local encrypted Restic snapshots and staged restore passed the actual deleted-project/incorrect-key runner probe and an installed root-CLI deleted-fixture restore at `2cebd11`, preserving bytes/mode and leaving live state untouched. External/off-host backup, retention/scheduling, whole-system restore, broken-update rollback, GPU/resource measurements and long gateway missions remain outstanding.

See [evidence](HAOS.md) and [release gates](RELEASE.md). A green desktop suite or syntax-checked harness does not close these gaps.
