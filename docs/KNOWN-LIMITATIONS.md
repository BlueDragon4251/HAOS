# Known limitations

HAOS is development, not an accepted production distribution. The master prompt remains the complete target.

- The bounded installed foundation gate passed at `2cebd11`: exact ISO bytes verified, actual UEFI/TCG installation and both guest receipts completed, covering Hermes health, fixture volume boundaries, observer/local-network denial, staged local recovery, UI/backend restart separation and offline queue persistence. The earlier policy-umask, DNS and systemd/procfs startup failures are corrected and evidenced. This does not accept the complete production distribution, graphical owner onboarding or physical hardware. Historical billing failures are distinct from current public-repository runs. Builds remain unsigned. Full SBOM/provenance, reproducible pins, Secure Boot/private updates unfinished.
- Writable binds retain POSIX ownership/ACLs; general owner-approved ACL/idmapped access unfinished. Same-system-disk data is conservatively denied. LUKS unlocking is owner work; hotplug/remote filesystems unsupported.
- Shared host networking now has a required socket-UID nftables guard for local/private destinations with narrow backend/DNS/reply exceptions. At `2cebd11`, the real runner kernel probe passed IPv4/IPv6/mapped-address denial, existing-connection revocation, backend self/reply exceptions, denied firewall mutation and preserved other-UID traffic. Both installed boots separately proved service-UID denial of a privileged localhost listener. AF_UNIX abstract sockets, resolver-change brokerage and complete egress/exfiltration policy remain incomplete. Inherited SELinux permissive configuration has no enforcing proof.
- Durable native missions exist; ordinary chat/voice/gateways are not unified with queue/trust identities.
- Complete upstream turn is not independent goal proof. Ambiguity blocks intentionally. Background cleanup, resumable downloads and parallel worktrees need further work.
- Native host GUI bridge access is withheld; safe broker, genuine capture and authenticated remote stream missing.
- Autonomous themes/skills lack accepted capability manifests, isolated generation/test, whole-theme atomic swap/watchdog/revocation.
- Provider/vault/local-model/budget provisioning unfinished. No provider-less probe proves a real model/Git mission.
- Task/event text may contain sensitive data; complete redaction/encryption/retention not guaranteed.
- Observer accounts reject inherited administrator groups, empty passwords and sudo authority before session start. Actual runner account/NOPASSWD/sudoedit probes and both installed guest observer checks passed at `2cebd11`. Separate root-console owner enrollment with password quality, per-invocation authenticated fixed CLI and rollback is implemented; actual runner PAM/sudo accepts the correct password and denies wrong/cached authentication, arbitrary commands and Python environment overrides. This runner fixture does not prove installed owner onboarding. Installer/bootstrap, graphical locking, recovery codes, automatic observer display behavior and review of all polkit/custom identity mechanisms remain open production gates.
- Owner-only local encrypted Restic snapshots and staged restore passed the actual deleted-project/incorrect-key runner probe and an installed root-CLI deleted-fixture restore at `2cebd11`, preserving bytes/mode and leaving live state untouched. External/off-host backup, retention/scheduling, whole-system restore, broken-update rollback, GPU/resource measurements and long gateway missions remain outstanding.

See [evidence](HAOS.md) and [release gates](RELEASE.md). A green desktop suite or syntax-checked harness does not close these gaps.
